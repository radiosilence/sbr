Each change adds one file under `unreleased/<section>/`, named for its pull request (`30-short-slug.md`), holding one `- **Lead.** Detail.` entry; sections are `breaking`, `added`, `security`, `changed`, `removed`, `fixed`, `tests`, `known-issues` and `internal`. CHANGELOG.md is generated from these files by `scripts/changelog.py` (`just changelog`) and is never edited by hand. A pull request adds its fragment and leaves CHANGELOG.md alone; the release pull request (`just release`) runs `--release X.Y.Z`, which turns `unreleased/` into that version and regenerates the file, so two open pull requests never conflict on it.
